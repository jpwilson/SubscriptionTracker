# SEO and AI answer-engine setup

How SubTracker is made findable in Google and Bing, and quotable by ChatGPT,
Claude, Gemini, Perplexity, Copilot and Grok. Written for whoever maintains the
site next — including future-you.

Last updated: October 2026.

---

## The one setting that matters: NEXT_PUBLIC_SITE_URL

Everything that needs an absolute URL — canonicals, Open Graph tags,
`sitemap.xml`, `robots.txt`, the JSON-LD, `/llms.txt` — reads a single constant:

```ts
// src/lib/site.ts
export const SITE_URL = (
  process.env.NEXT_PUBLIC_SITE_URL || 'https://subscription-tracker-vert.vercel.app'
).replace(/\/+$/, '')
```

**Why this was urgent.** Before this change, the sitemap, canonicals, OG tags
and JSON-LD all pointed at `https://subtracker.app`, a domain that has no DNS
record. A canonical pointing at a host that does not resolve tells Google and
Bing that the real version of every page lives somewhere they cannot reach, so
the pages they *can* reach look like duplicates of a dead original. The sitemap
listed seven URLs on that dead host, one of which (`/vs-truebill`) did not exist
at all.

**If you buy a domain** (subtracker.app or anything else):

1. Point the domain at the Vercel project.
2. In Vercel → Project → Settings → Environment Variables, set
   `NEXT_PUBLIC_SITE_URL=https://yourdomain.com` (no trailing slash) for
   Production.
3. Redeploy. Canonicals, sitemap, robots, JSON-LD and the llms files all follow.
4. Add the new domain in Google Search Console and Bing Webmaster Tools, and
   submit the new sitemap.
5. In Vercel, make the old host 308-redirect to the new one so nothing is lost.

Nothing else in the codebase hardcodes a hostname. `npm run check:seo` fails if
`subtracker.app` reappears in any page's HTML.

## How pages reach crawlers (no JS required)

The marketing pages are **statically rendered at build time** by the Next.js app
router. The full text of each page is in the HTML response body before any
JavaScript runs. That matters because Googlebot renders JS slowly and in a second
pass, and GPTBot, ClaudeBot, PerplexityBot and most AI fetchers do not render it
at all.

There is no user-agent sniffing anywhere. Bots and humans get byte-identical
HTML, which avoids any cloaking risk.

Confirm it yourself after a build:

```bash
npm run build
npm start -- -p 3001
curl -s http://localhost:3001/vs-rocket-money | grep -c "Rocket Money"
```

The header, footer, comparison tables and FAQ are all server components. The
home page is a client component (it has an interactive calculator) but still
server-renders its text, which is why it reports ~1,660 words of crawler-visible
content.

## What exists

### Pages

| URL | What it is for |
|---|---|
| `/` | What SubTracker is, features, how it works, pricing, FAQ teaser |
| `/pricing` | Free plan, the three published-but-unavailable Premium prices, and what it does not do |
| `/faq` | 15 questions answered from how the app actually behaves |
| `/alternatives` | Honest rundown of subscription trackers ("best X app" queries) |
| `/vs-rocket-money` | Manual tracking vs bank-connected detection |
| `/vs-bobby` | Web app vs iOS-only tracker |
| `/vs-ynab` | Subscription tracker vs full budgeting system |
| `/how-to-cancel-subscriptions` | Guide (pre-existing, re-fitted) |
| `/find-forgotten-subscriptions` | Guide (pre-existing, re-fitted) |
| `/subscription-savings-guide` | Guide (pre-existing, re-fitted) |
| `/login` | Sign in / sign up (crawlable, marked `thin`) |

`/vs-truebill` 308-redirects to `/vs-rocket-money` (Truebill was renamed Rocket
Money in 2022, so a separate page would be the same comparison under an old
name). The redirect lives in `next.config.js`.

### Files

- `/robots.txt` — generated by `src/app/robots.ts`. `Allow: /` for everyone,
  explicit Allow groups for OAI-SearchBot, ChatGPT-User, GPTBot,
  Claude-SearchBot, Claude-User, ClaudeBot, PerplexityBot, Perplexity-User,
  Google-Extended, Googlebot, bingbot, Applebot, Applebot-Extended,
  DuckAssistBot, meta-externalagent and CCBot. Only the private app routes
  (`/api/`, `/dashboard`, `/subscriptions`, `/analytics`, `/insights`,
  `/profile`, `/payment`, `/auth/`, `/test`) are disallowed. Absolute `Sitemap:`
  line.
- `/sitemap.xml` — generated by `src/app/sitemap.ts` from `PUBLIC_PAGES`.
- `/llms.txt` and `/llms-full.txt` — real `text/plain` route handlers
  (`src/app/llms.txt/route.ts`, `src/app/llms-full.txt/route.ts`) generated from
  the content modules. `/llms-full.txt` used to 404. Note that the published
  research on llms.txt shows no measurable citation benefit; these exist because
  they are cheap and correct, not because they are a growth lever. Do not spend
  effort on them.
- `/og-image.png` — 1200×630 social card. The metadata referenced this file
  before it existed, so every preview was broken.
- `/<indexnow-key>.txt` — see IndexNow below.

### Structured data

Rendered as inline `<script type="application/ld+json">` so non-JS crawlers see
it. Built by `src/lib/seo.ts`:

- **Organization** and **WebSite** — site-wide, in `src/app/layout.tsx`.
- **WebApplication** — site-wide. `offers` come from `PLANS` in
  `src/content/product.ts`, which carries the prices Stripe checkout actually
  charges.
- **FAQPage** — on `/faq`, generated from the same array the page renders.
- **BreadcrumbList** — on every subpage.
- **Article** — on the comparison pages and the three guides.
- **ItemList** — on `/alternatives`.

**There is no `aggregateRating` anywhere, and there must not be.** The previous
JSON-LD claimed 4.8 stars from 1,247 reviews. Those reviews do not exist.
Invented review markup is a manual-action risk with Google and, if an answer
engine repeats it, a straightforward false claim about the product. The check
script fails the build if `aggregateRating` reappears.

Google deprecated FAQ rich results in May 2026, so the FAQPage markup will not
produce stars in search. It is kept because it mirrors visible text and answer
engines still parse it.

## Content rules (please keep these)

Everything on the public pages has to be checkable from this repository or from
the live app. In practice that meant removing a fair amount:

- Three testimonials with invented names, job titles, cities and dollar savings.
- "Join thousands…", "Save 30% on average", "The average person has forgotten
  2–5 subscriptions / $40–$300 a month".
- "Based on real user data and optimization strategies" under the savings
  calculator. This one survived the first pass and was caught in review: the
  calculator runs on hardcoded per-category prices and hardcoded savings rates,
  and there is no user data to base anything on. The line now reads
  "Illustrative estimate based on assumed costs and savings; actual results
  vary" and spells out both assumptions.
- "Bank-level encryption", "encrypted end-to-end", "we have zero knowledge of
  your spending habits". The data sits in Postgres and is not end-to-end
  encrypted. What *is* true — no bank connection, no card credentials, CSV
  export, Stripe handles payment details — is on the page now.
- Features that do not exist: email scanning, screenshot import, bank sync,
  family account management, automatic price-increase detection.
- **Notifications.** `reminder_days_before` is stored per subscription and
  returned by the API, nothing consumes it, and there is no mailer, cron or
  push registration anywhere in the repo. Every "we'll alert you / remind you /
  tell you about price increases" line is gone; the pages now say a next payment
  date and reminder window are stored and shown in the app, and that SubTracker
  sends nothing.
- **Account deletion.** `handleResetAccount()` in `src/app/profile/page.tsx`
  deletes the subscriptions, clears two localStorage flags and reloads. It does
  not delete the auth user or the profile row. The FAQ and privacy copy now
  describe CSV export plus Reset Account, and say plainly that removing the
  sign-in itself is not yet a button.
- **Smart Insights.** The screen is blurred behind a Premium upgrade overlay for
  anyone who is not Premium, which is everyone (below), so it is not a free
  feature and was removed from the free lists. Its unused-subscription detection
  also uses `Math.random()` rather than recorded usage, and its "costs more than
  average" line compares against hardcoded category averages rather than your
  other subscriptions — so those two descriptions are gone from the shared
  content and the home page examples, not merely relabelled.
- **Premium as a purchasable thing.** `isPremiumUser()` returns `false`
  unconditionally, there is no Stripe webhook route, and
  `/payment/success` only simulates processing — so paying unlocks nothing.
  Premium is now presented everywhere as a published price for a plan that
  cannot be switched on: `status: 'planned'` in `PLANS`, `schemaPrice: null` so
  it never becomes an `InStock` `Offer` in JSON-LD, "Not available yet" badges
  on the cards, and the home/login CTAs point at `/pricing` instead of Stripe
  checkout.
- The category count was wrong in three different places (20, 12 and 9). It is
  12, from `DEFAULT_CATEGORIES` in `src/app/api/categories/route.ts`.
- The home page advertised Premium at $5/month while checkout charges $8
  month-to-month. It now says $5/month billed annually ($60/year), or $8
  month-to-month, which matches `src/app/payment/page.tsx`.

Competitor facts on the comparison pages are general, hedged, dated
("as of October 2026"), sourced to the competitor's own site or App Store
listing, and each page has a "where they are stronger" section. Details that
could not be confirmed were left out rather than guessed — notably Rocket
Money's current Premium price and Monarch Money's plan prices.

If you add a claim, add the source. If you cannot source it, do not write it.

## Adding a new page

1. Create `src/app/<slug>/page.tsx`. Use `MarketingShell` for the chrome.
2. Export metadata with the shared helper — this gives you the canonical, OG and
   Twitter tags for free:

   ```tsx
   export const metadata = buildMetadata({
     title: 'Something specific, under 60 characters',
     description: 'One or two sentences, 140-160 characters.',
     path: '/your-slug',
   })
   ```

3. Add a `<JsonLd>` block with `breadcrumbSchema(...)` and, if it is an article,
   `articleSchema(...)`.
4. **Register it in `PUBLIC_PAGES` in `src/lib/site.ts`.** That one entry adds it
   to the sitemap, the header, the footer, `/llms.txt` and the check script.
5. Give the page exactly one `<h1>`, with the brand and the category in it where
   that reads naturally, and make the first sentence say what the thing is and
   who it is for.
6. Run `npm run build && npm start -- -p 3001` then `npm run check:seo`.
7. After deploying, run IndexNow (below).

New marketing pages should have no render-blocking additions: use inline SVG
icons (lucide) rather than images where possible, and if you do add an image,
set explicit `width`/`height` and `loading="lazy"` on anything below the fold.
There are currently no raster images on the marketing pages apart from the OG
card, which is never rendered in-page.

## Verification: Google Search Console and Bing (owner steps)

**No verification tokens are committed to this repo**, deliberately — a
placeholder token is worse than none, because it looks verified and is not.
These steps need the owner signed in.

### Google Search Console

1. Go to <https://search.google.com/search-console> and sign in.
2. Add a property.
   - If you own a domain: choose **Domain**, enter the bare domain, and add the
     `TXT` record it gives you at your DNS provider. This covers every subdomain
     and both protocols, and is the best option.
   - On the Vercel subdomain you cannot edit DNS, so choose **URL prefix** with
     `https://subscription-tracker-vert.vercel.app` and verify with the **HTML
     tag** method. Paste the token into `src/app/layout.tsx`:

     ```ts
     export const metadata: Metadata = {
       // ...
       verification: { google: 'PASTE_TOKEN_HERE' },
     }
     ```

     Deploy, then click Verify. (Better: put it in an env var and read it, so the
     token is not in git.)
3. Submit `https://<host>/sitemap.xml` under **Sitemaps**.
4. Check **Settings → Search generative AI**. The default is to be included in AI
   Overviews and AI Mode; leave it on.
5. The **Generative AI** performance report shows impressions from AI surfaces.

### Bing Webmaster Tools

1. Go to <https://www.bing.com/webmasters> and sign in.
2. Use **Import from Google Search Console** — it carries the verification over
   and is much faster than verifying again.
3. Otherwise add the site and use the meta-tag method, adding
   `verification: { other: { 'msvalidate.01': 'TOKEN' } }` to the metadata.
4. Submit the sitemap.
5. Bing matters out of proportion to its search share: it feeds Copilot,
   DuckDuckGo, and historically part of ChatGPT's search.

Worth doing at the same time: make sure the site is reachable by Brave's crawler
(Claude's search uses Brave as a listed subprocessor), and post about the product
on X, because Grok searches X directly.

## IndexNow

IndexNow tells Bing, Yandex, Seznam and Naver that URLs changed. Google does not
use it.

- Key: `56fd194fbf8271a96cf86b9b7eded128`
- Key file: `public/56fd194fbf8271a96cf86b9b7eded128.txt`, served at
  `https://<host>/56fd194fbf8271a96cf86b9b7eded128.txt`
- Script: `scripts/indexnow.mjs`

```bash
npm run indexnow              # dry run: prints the payload, submits nothing
node scripts/indexnow.mjs --submit   # actually POSTs to api.indexnow.org
```

The script reads the live `sitemap.xml`, so it always submits the current page
list. Run it after a deploy that changes public page content — not on every
deploy, and not in a loop. If you change the key, rename the file in `public/`
and update the default in the script (or set `INDEXNOW_KEY`).

## The automated check

```bash
npm run build
npm start -- -p 3001 &
npm run check:seo
```

`scripts/check-seo.mjs` reads the page list out of `src/lib/site.ts` and asserts,
for every public page, against the real HTTP response:

- HTTP 200, a unique `<title>`, a meta description
- an absolute self-referencing canonical on the expected host
- exactly one `<h1>`, `lang` on `<html>`
- `og:title`, `og:description`, `twitter:card`
- at least one JSON-LD block, and every block parses as JSON with an `@type`
- more than 300 words of crawler-visible text with script/style/svg stripped
  (skipped for pages marked `thin`, i.e. `/login`)
- no `aggregateRating`, no reference to `subtracker.app`

Plus: `robots.txt` has every expected bot group and an absolute `Sitemap:` line,
`sitemap.xml` is XML and contains every public URL with a `lastmod`,
`/llms.txt` and `/llms-full.txt` are `text/plain` and not HTML, an unknown path
returns 404 rather than a 200 page shell, and `/vs-truebill` permanently
redirects.

Set `CHECK_BASE_URL` if you run the server on a different port.

### Building locally

`npm run build` needs a few environment variables present (not valid — just
present), because some routes construct Supabase and Stripe clients at module
scope:

```bash
export DATABASE_URL="file:./dev.db"
export NEXT_PUBLIC_SUPABASE_URL="https://placeholder.supabase.co"
export NEXT_PUBLIC_SUPABASE_ANON_KEY="placeholder-anon-key"
export STRIPE_SECRET_KEY="sk_test_placeholder"
```

These are throwaway values for a local build only. Do not commit them, and do
not use them in Vercel.

## Measuring whether any of this worked

- **Google Search Console** → Performance → Generative AI report.
- **Bing Webmaster Tools** → AI performance.
- **Referrals** in PostHog / Vercel Analytics: look for `chatgpt.com`,
  `perplexity.ai`, `claude.ai` referrers and `utm_source=chatgpt.com`.
- **Monthly manual check**: ask ChatGPT, Claude, Perplexity, Gemini and Grok
  "best free subscription tracker app", "subscription tracker without bank
  access", "SubTracker vs Rocket Money" and see whether the site is cited.

The biggest remaining lever is not on this site at all. Answer engines cite pages
that other sites talk about. Directory listings, a Reddit or Hacker News post
that is actually useful, a mention in someone's "best subscription trackers"
roundup, and posts on X (which Grok searches directly) will move the needle more
than any further on-page work.

## Known gaps, left deliberately

- **No `sameAs` in the Organization schema.** The repo mentions
  `twitter.com/subtracker`, but that handle could not be confirmed from here. A
  `sameAs` pointing at a profile you do not own is a false statement about the
  company. Add it once you have confirmed the handle (and a GitHub org, an App
  Store listing, and so on).
- **No `contactPoint` email in the schema.** `support@subtracker.app` is on a
  domain with no DNS, so mail to it cannot be delivered. Put a working address in
  once there is one.
- **No verification tokens**, for the reason above.
- **Rocket Money's Premium price and Monarch Money's plan prices** are not
  stated. Both vary and could not be confirmed; the pages link out instead.
- **`README.md` still lists features and plan details that the marketing pages
  no longer claim** (20 categories, auto-import, the Enterprise feature list).
  It was left alone to keep this change focused on the public pages, but it is
  worth a pass.
- **Premium entitlement is stubbed in the app** — `isPremiumUser()` in
  `src/lib/feature-gates.ts` returns `false` unconditionally,
  `use-user-profile.ts` hardcodes the free tier, and there is no webhook route
  to grant an entitlement after a Stripe payment. Three things have to land
  together before the marketing copy can change: a `stripe` webhook route that
  verifies the signature, a persisted entitlement, and `isPremiumUser()` reading
  it. Until then Premium stays `status: 'planned'` with `schemaPrice: null` in
  `src/content/product.ts` — flipping those two fields and the copy that keys off
  them is the whole change on this side.
- **Reminder delivery does not exist.** `reminder_days_before` is written and
  read and never acted on. A mailer or a scheduled job plus a notification
  preference would make the removed reminder copy true again; the honest version
  is in `FEATURES` and `LIMITATIONS` in `src/content/product.ts`.
- **Insights are partly simulated.** `src/app/insights/page.tsx` needs a real
  `lastUsed` field instead of `Math.random()`, and a real baseline instead of
  the hardcoded `categoryAverages`, before the screen can be described at all.
